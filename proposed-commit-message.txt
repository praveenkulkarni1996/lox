Implement return statements (#17).

Adds support for `return expr?;` (and bare `return;`) per Crafting
Interpreters §10.5 and issue #17.

- New AstStatement::Return(Option<AstExpression>) variant and parser
  support in parse_statement.
- LoxError::Return(Value) used as a control-flow signal (caught only at
  the LoxFunction call boundary in call_function; top-level returns
  produce a clear "Can't return from top-level code." error).
- All existing control structures (blocks, if, while, desugared for)
  correctly unwind on return via the existing Result + ? propagation.
- Bare `return;` yields nil. Early returns short-circuit. Returns of
  expressions (including from deep nesting and recursion) are supported.
- Added parser tests for the new statement form (bare, with value, in
  blocks, error cases).
- Added interpreter tests for the cases listed in the issue: early
  return short-circuits, value return mid-body, correct unwinding from
  nested blocks/loops, and bare return producing nil.
- Added test_function_fibonacci_recursion_with_return exercising the
  classic recursive Fibonacci from the book (base case early return +
  return of fib(n-2)+fib(n-1) expr). Verified with fib(20) == 6765.

The change is self-contained on top of function declarations. All
pre-commit checks (fmt --check, clippy -D warnings, test, doc --no-deps)
pass.
